What this demo is about

Metric traceability for O2C process mining

The notebook reconstructs cases from the event log, compares the assumed happy path with actual variants, calculates friction and control metrics, and then turns those findings into transformation choices using plain finance language.

Learning objectives

  • Calculate variant count, lead time, wait time, rework rate, and STP rate from an event log.
  • Show why not all O2C delay is suitable for automation.
  • Use mined behaviour to support eliminate, standardize, enable, assure, and monitor decisions.

Run mode

  • Supported mode: Colab
  • Demo type: notebook launch guide
  • Primary launch surface: index.html

Teacher cue

Ask: “What does the happy path fail to show, and which delays should never be automated away without redesigning the process first?”

Business decision

What decision this demo helps you make

Use this demo to decide which O2C friction should be removed or standardized, which stable path is ready for workflow enablement, and which exceptions should remain under named human ownership and control review.

Self-service reuse

What you can build on from here

What you can enhance on your own

  • Add more entities, policies, and exception classes once the base notebook is stable.
  • Add scenario comparisons or future-state event logs for post-redesign analysis.
  • Add your own export tables for management packs or workshop handouts.

How to adapt this demo to your use case

  • Replace the fictional event log with sanitized events from your own process or course setting.
  • Revalidate metric assumptions, thresholds, and control definitions with relevant domain owners.
  • Keep the notebook diagnostic and educational until the workflow has been tested in your own environment.

Audience fit

This notebook supports CFO workshops, treasury, controllership, O2C operations, faculty, and learners because it keeps the event-log logic transparent enough to challenge and adapt.
