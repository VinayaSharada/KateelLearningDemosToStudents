What this demo is about

Students move beyond a browser simulation and inspect how payment history, invoice terms, dispute signals, channel mix, and seasonality can be turned into late-payment risk features and then into a predicted payment date per invoice, rolled up into a day-by-day treasury inflow calendar.

Why Colab helps here

The notebook keeps the data generation, feature engineering, model scoring, export logic, and governance notes visible, so the class can critique the modeling assumptions instead of only consuming a final recommendation.

Self-Service Use

Who this is for

Useful for CFOs, treasury teams, collections leaders, faculty, and learners who want a reusable invoice-level cash-timing workflow.

How to adapt it

Download the template, map your ERP export into the same columns, re-run the notebook, and compare the baseline versus predicted inflow calendar using your own open invoices.

What to take back

Export the action queue, predicted payment dates, daily inflow views, and run summary to support your own short-term cash planning discussion.

What you can enhance on your own

Enhancement ideas

How to adapt this demo to your use case

Start with `invoice_data_template.csv`, keep scoring separate from retraining, and confirm feature definitions, approval rules, and economic assumptions with your treasury and collections owners.

Run Modes and Expectations

Colab

Best for a classroom walkthrough with zero local setup and visible Python cells for each modeling step, followed by a text explanation block after every code cell.

What students do

Generate synthetic invoices or upload an open-invoice extract for scoring, engineer risk features, train a late-payment classifier and a days-late regressor, score invoices, export a collections action queue plus treasury forecast files, and estimate cash release from better DSO discipline.

Wait expectation

The notebook is lightweight by design. Most delay comes from package startup and first-run Colab environment loading.

How to use it

  1. Open the notebook in Colab and run the setup cell.
  2. Optional: download the data template, fill it with your own ERP invoice export, and upload it back in instead of using synthetic data.
  3. Review the synthetic or uploaded invoice data and ask which features should matter most.
  4. Run the model section and compare predicted late-payment risk with invoice amount and customer context.
  5. Use the priority table and collections action queue to discuss which invoices should receive immediate attention.
  6. Compare the due-date baseline and predicted-date forecast over 7, 14, and 30 days and decide which one you'd trust for short-term cash planning.
  7. Export the treasury deliverables: predictions, daily inflows, collections queue, calendar import, and run summary.
This is a teaching notebook, not a production collections model. The point is to make feature choice, model behavior, and trade-offs visible enough for classroom critique.

Control boundary

What remains illustrative, and what must stay human

Data and evidence note

This notebook uses fictional invoice data by default and a template-based upload path so learners can understand the workflow without exposing live customer data.

Human approval point

The model can support prioritization and forecast timing, but collections strategy, customer treatment, and rollout still require human review.

Safe reuse guidance

Reuse the template, model logic, and export pack, but validate fields, action labels, thresholds, and approvals with your own treasury and collections teams.
