What this demo is about

Threat modeling at scale

STRIDE is a systematic threat modeling methodology that helps security professionals and architects identify threats to system security.

Learning objectives

  • Apply STRIDE methodology systematically to architectures
  • Design data flow diagrams with security properties
  • Identify threat patterns from architecture decisions
  • Map threats to mitigations and controls

Run modes

  • Supported modes: Browser
  • Demo type: Interactive browser-based threat modeler
  • Primary launch surface: index.html

Before you start

No installation or API keys required. Loads entirely in your browser with a pre-built sample DFD to get started immediately.

Includes 20+ pre-built threat rules covering all STRIDE categories.

Business or domain context

Why threat modeling matters

Most security breaches result from exploitable design flaws, not implementation bugs. Threat modeling shifts security left.

Core context

Threat modeling is a structured methodology to identify and prioritize security threats before code is written.

STRIDE specifically focuses on six threat categories that align with system architecture elements.

STRIDE categories

●Spoofing - Identity attacks
●Tampering - Data modification
●Repudiation - Denial of actions
●Information Disclosure - Privacy leaks
●Denial of Service - Availability attacks
●Elevation - Privilege escalation

What students should note

Threat modeling is not a one-time activity. Models evolve as systems change, and threats are re-evaluated with each architectural decision.

How to use the demo

Recommended classroom flow

Scenario 1: Start with sample DFD

  • Launch demo and examine the pre-built DFD (User → Web API → Database)
  • Click "Analyze Threats" to see auto-generated threats
  • Review threat descriptions, severity levels, and mitigations
  • Discuss why each threat applies and how to fix it

Scenario 2: Design a new architecture

  • Clear the canvas and design a different system (e.g., mobile app → API → third-party payment gateway)
  • Configure security properties for each entity
  • Analyze and compare threat profiles
  • Iterate: add encryption, fix inputs, compare results

Scenario 3: Mitigation challenge

  • Start with a vulnerable DFD (unencrypted flows, no auth, no validation)
  • Run threat analysis and review findings
  • Students propose fixes (enable encryption, add auth, etc.)
  • Re-run analysis to verify threats are mitigated

Input variables explained

  • Entity Type: Role in the system (User, API, Database, etc.)
  • Data Flow: Communication channels between entities
  • Protocol: How data is transmitted (HTTP, HTTPS, SSH, etc.)
  • Security Properties: Authentication, encryption, validation, logging

Outputs and interpretation

How to read the threat results

Threat information

  • Severity: Critical, High, Medium, Low - based on impact
  • Category: Which STRIDE element the threat applies to
  • Description: What the threat is and how it could be exploited
  • Mitigation: Concrete steps to prevent or reduce the threat

What to notice

  • Unencrypted data flows trigger multiple threats
  • External entities without authentication enable spoofing
  • Missing input validation leads to injection attacks
  • Trust boundaries increase threat surface area

Discussion and reflection

  • Which threats are most critical to your business?
  • What's the cost of mitigation vs. the cost of a breach?
  • Are there threats you didn't expect?
  • How would you prioritize fixes for a real system?

Faculty guide

Prompt for discussion or assessment

Assessment Question: Design a DFD for a healthcare system that handles patient records. Run threat analysis. Identify at least 3 critical threats and propose mitigations that balance security and usability.

Suggested Follow-up: Compare your threat list to OWASP Top 10 and CWE/SANS. Are there threats that STRIDE catches but the Top 10 misses? Why?
