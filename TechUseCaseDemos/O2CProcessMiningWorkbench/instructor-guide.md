# Instructor Guide

## Business decision

Decide which O2C delay should be removed or standardized upstream, which stable path is ready for workflow enablement, which exceptions must remain human-reviewed, and which metrics should be monitored after launch.

## Facilitator mode

Time: `8 minutes`

1. Start on the assumed happy path and ask where the class expects orders to wait.
2. Reveal the top variants, then expand to all variants and point out credit-hold loops, delivery disputes, short-payment review, and unapplied cash.
3. Filter high-value and control-violation cases.
4. Show lead time, wait time, exception ageing, and straight-through-processing rate.
5. Move to the decision board and ask what should be eliminated, standardized, enabled, assured, and monitored in the next 30 days.

## Participant exercise

Time: `10-12 minutes`

Ask participants to:

1. Filter the event log to one entity or exception type.
2. Identify the biggest source of avoidable delay.
3. Choose one eliminate/standardize action, one enable action, and one monitoring trigger.
4. Explain what should remain controlled and human-reviewed.

## Teaching cues

- The designed O2C flow is not the same as the executed flow.
- Wait time is usually the bigger transformation opportunity than touch time.
- A control breach is not automatically an automation opportunity.
- High-value cases deserve attention, but repeat low-value rework can still destroy capacity.
- Workflow enablement belongs on the stable path, not on the unstable path.

## Expected output

Participants should produce:

- one prioritized friction point
- one root-cause hypothesis
- one eliminate or standardize action
- one workflow-enablement action
- one control or human-review boundary
- one 30-day monitoring trigger
