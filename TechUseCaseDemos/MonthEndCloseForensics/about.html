About: Month-End Close Forensics

Concept, learning objectives and how to adapt this demo to your close

Overview

The month closes with three line items over budget. Explaining them usually takes days of cross-team email archaeology. Here a forensic agent swarm attributes each one with evidence: a freight spike that traces to a signed approval (the supply-chain war room's expedite — governance working, not failing), a cloud leak pinned to a specific engineering deploy while a 48% contract discount sat unused, and SaaS seats nobody has opened in 95 days. Fictional company; all data synthetic.

The architecture idea (the part worth stealing)

Classify before you convene. Red ink is not one thing: APPROVED, AVOIDABLE LEAK and PROCESS GAP each deserve a different conversation. The joins that produce those verdicts — cloud billing × deploy log × contract clause, ledger × approvals register, SaaS spend × usage telemetry — are deterministic; the agents narrate and draft, and every corrective action awaits a human signature.

The Swarm Replay (new in this demo)

The 🎭 tab replays the actual recorded trace of a live forensic run: agent cards pulse while thinking, tool chips appear as each specialist reads its governed data, and a timestamped ticker narrates the delegations. Nothing is scripted — it is event-sourced from a real run. In the live tier you press one button and watch it happen in real time.

Learning objectives

  • Separate governed variances from surprises — a variance with a signature is a feature.
  • See where close answers actually live: in the systems Finance never opens, joined by keys every company already has.
  • Attribution without blame: PR-412 is a fact; the fix is a tagging policy, not a bigger budget.

Run modes

Browser (this page): pre-computed scan, findings, cloud drill-down and the recorded swarm replay; no setup, no keys.
Live tier (registered participants): the full pipeline with a threshold slider, and the Swarm Theater running the forensic swarm live (Anthropic / OpenAI / OpenRouter / Groq via a .env file).

How to adapt this demo to your use case

Seven CSV contracts match exports you already have: ERP trial balance, budget, cloud console billing, git/deploy log, vendor contract register, approvals file, SSO usage report. Run it read-only beside one real close and count the emails it deletes — that number is the business case.
