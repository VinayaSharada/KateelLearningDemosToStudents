What this demo is about

Concept first, interaction second

Some students only have an official/corporate Windows laptop that is locked down: no admin rights, no WSL2, no VirtualBox, no Docker. This demo gives them a genuine Linux shell anyway, by running a real x86 CPU emulator (v86) compiled to WebAssembly, entirely inside the browser tab. It is not a scripted or fake terminal - it boots an unmodified Buildroot Linux kernel and runs real commands.

Learning objectives

  • Practice core Linux shell commands (filesystem navigation, processes, basic networking) with zero setup.
  • Understand what a virtual machine is by using one that visibly boots a kernel in front of you.
  • Get comfortable experimenting freely - the machine resets to a clean state on every restart.

Run modes

  • Supported modes: Browser
  • Demo type: Interactive browser demo (real emulator, not scripted)
  • Primary launch surface: index.html

Before you start

First boot downloads a small (~10 MB) Linux kernel image from public CDNs, so it needs outbound internet access and can take 10-30 seconds depending on connection speed.

Nothing persists once the tab is closed - there is no save/restore wired into this demo.

Why this matters

Access, not just convenience

This demo exists to remove a real barrier: students without a personal machine, and without permission to install anything on their official laptop, still deserve hands-on practice with a Linux shell.

How it works

v86 JIT-compiles or interprets real x86 machine instructions inside WebAssembly, emulating actual PC hardware (CPU, BIOS, disk, network device). The guest kernel has no idea it isn't running on physical hardware - so every command really executes inside the emulated machine, isolated from the host laptop.

Concepts covered

●Linux fundamentals
●Shell scripting basics
●Virtualization concepts
●Accessibility for restricted devices

What students should note

This is CPU emulation, not native execution - it is fine for shell practice and small scripts, but not a substitute for a real dev machine on compute-heavy work.

How to use the demo

Recommended classroom flow

List of steps

  • Open the demo and click Start Linux.
  • Wait for the kernel to download and boot (progress is shown).
  • Click the black terminal area to focus it, then type shell commands.
  • Use Restart at any time to return to a clean machine.

Suggested first commands

  • ls /, cd /etc, cat /etc/os-release - explore the filesystem.
  • ps, whoami, uname -a - inspect the running system.
  • ping -c 3 example.com, curl example.com - test basic networking.

Facilitator notes

  • Works on locked-down/official laptops as long as the browser can reach the internet - verify this once on your institution's network before class.
  • Each student's session is independent and local to their own browser tab.

Faculty guide

Prompt for discussion or assessment

Frame the activity around access and virtualization: what does it mean that this Linux machine "isn't really there" on the laptop's hard drive?

Suggested interpretation prompt: Ask students to compare what they could and couldn't do here versus a real installed Linux system, and why.
