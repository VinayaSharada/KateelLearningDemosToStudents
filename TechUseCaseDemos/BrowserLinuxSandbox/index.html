What to try once it boots

Scope: this is a real but disposable Linux machine that exists only in this browser tab. Nothing you do here touches your actual laptop, and nothing you do here is saved once you close the tab.

  • Explore the filesystem: ls /, cd /etc, cat /etc/os-release
  • Check what's running: ps, whoami, uname -a
  • Try networking: ping -c 3 example.com, curl example.com
  • Write a script: vi hello.lua then run it with lua hello.lua

Standard demo guide

Use this demo in a logical learning sequence

First boot downloads a ~10 MB kernel image, so allow 10-30 seconds depending on the network. Later restarts on the same page are instant.

What this demo is about

This runs a real, unmodified Buildroot Linux kernel using v86, an open-source x86 PC emulator compiled to WebAssembly. It is a genuine virtual machine, not a scripted or simulated terminal.

Learning objectives

  • Practice core Linux shell commands without needing any local install permissions.
  • Understand the difference between a host operating system and a virtualized guest.
  • Experiment freely - the machine resets to a clean state on every restart.

Run mode and expectations

  • Supported modes: Browser only
  • No installs, no admin rights, no Docker/WSL2/VirtualBox required
  • Works on locked-down corporate/official laptops, as long as the browser can reach the internet

Step 1: Start the machine

Click Start Linux. The browser downloads a small Linux kernel image, then boots it inside a virtual CPU running in your browser tab.

Step 2: Click the screen, then type

Click inside the black terminal area to give it keyboard focus, then use the shell like any other Linux terminal.

Step 3: Restart to reset

Use Restart to reboot back to a clean machine at any time - useful between student attempts or exercises.

Why this exists

Some students only have an official/corporate Windows laptop with no admin rights - no WSL2, no VirtualBox, no Docker. This demo gives them a real Linux shell anyway, entirely inside the browser, using WebAssembly-based CPU emulation instead of a hypervisor.

Requirements and limits

  • Needs an unrestricted-enough browser and outbound internet access to load the emulator library and kernel image from public CDNs.
  • Performance is CPU-emulation speed, not native - fine for shell practice, not for heavy compute.
  • Nothing persists after the tab closes; there is no save/restore wired into this demo.
