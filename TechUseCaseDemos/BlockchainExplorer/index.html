Bitcoin: Proof of Work & Block Structure

Understand how Bitcoin miners compete to add blocks to the blockchain through computational proof of work.

⚡ Quick Start Guide

Follow these 4 steps to understand Bitcoin mining:

1

Set Difficulty: Start with 2 zeros

👉 Change the "Difficulty" field to 2 (or leave at default)

📊 Notice: The difficulty target shows how many leading zeros the hash needs

💡 Bitcoin adjusts this every 2 weeks to maintain 10-minute blocks

2

Click "Start Mining" or Increment Nonce Manually

👉 Either click ⛏️ Start Mining (automated) or use the +1 button repeatedly

📊 Watch the Block Hash update with every nonce change. Most hashes don't start with 00

💡 This is what miners do: try billions of nonce values per second

3

Watch for the "Difficulty Match" Message

👉 Keep incrementing until you see ✓ Difficulty target met!

📊 Mining stops. The hash now starts with the required zeros (e.g., "00ab...")

💡 This nonce value gets included in the block. An attacker would need to redo this work

4

Increase Difficulty & Try Again

👉 Change difficulty to 3 (or higher) and reset. Mining becomes harder

📊 It takes many more hash attempts. Time = Cost = Security

💡 Higher difficulty = more computation required = stronger security but slower blocks

📚 Understanding Bitcoin Mining

What is Proof of Work?

Bitcoin miners compete to solve a computational puzzle: find a nonce (number used once) such that the block header's SHA-256 hash meets a difficulty target. The difficulty target is expressed as a minimum number of leading zeros in the hash.

Why does this matter for finance?

PoW creates an economic barrier to attacking the network. An attacker would need to control >51% of total hash power to rewrite history, which costs billions in electricity and hardware. This trustless consensus is Bitcoin's key innovation.

Block Structure

Version: Protocol version (currently 4)

Previous Block Hash: Links to the prior block (chain immutability)

Merkle Root: Hash of all transactions in this block

Timestamp: When block was created (Unix format)

Difficulty Target: How many leading zeros required

Nonce: The value miners increment to find a valid hash

📚 Key Ethereum Concepts for Finance

Why Accounts Instead of UTXOs?

Accounts make it easier to track balances and enable stateful smart contracts. Finance applications (lending, derivatives) need persistent state.

Gas: Computational Pricing

Gas prevents infinite loops and prices computation. Each EVM opcode costs a specific amount of gas. This is critical for DeFi: complex strategies cost more gas than simple transfers.

Impact on Finance

DeFi protocols must optimize for gas efficiency. During network congestion, gas prices spike (sometimes 10-100x), making small transactions uneconomical. This affects trading, lending, and staking decisions.

Smart Contracts: Solidity & EVM Execution

How smart contracts are written, compiled to bytecode, and executed on the Ethereum Virtual Machine.

⚡ Quick Start Guide

Follow these 4 steps to understand smart contract execution:

1

Read the Solidity Code (Top Left)

👉 Look at the SimpleToken contract—it's an ERC-20 token

📊 Notice: State variables (totalSupply, balances), constructor (initialization), functions (transfer, approve)

💡 This is the source code. Developers write Solidity. It's similar to JavaScript but for blockchain

2

See the Compiled Bytecode

👉 Look at the bytecode section (top right) - it's unreadable hex

📊 Bytecode: "6080604052..." is machine-readable form of Solidity

💡 Solidity compiles to bytecode → EVM executes bytecode. You never run the source directly

3

Disassemble Bytecode to EVM Opcodes

👉 Click "📖 Disassemble to Opcodes" button

📊 A table appears showing: PC (position), Opcode (PUSH, ADD, SLOAD, etc.), Gas cost, Description

💡 These are the "machine instructions" the EVM understands. Each costs gas. More opcodes = more expensive

4

Execute a Function and See State Change

👉 Select "transfer" and click "▶️ Execute"

📊 State Changes table shows: balances[sender] decreases, balances[to] increases

💡 This is how DeFi works: code automatically updates state when conditions are met. No bank needed

Solidity Source Code (Example: ERC-20 Token)

pragma solidity ^0.8.0;

contract SimpleToken {
    string public name = "Demo Token";
    uint8 public decimals = 18;
    uint256 public totalSupply = 1000000 * 10 ** 18;

    mapping(address => uint256) public balances;
    mapping(address => mapping(address => uint256)) public allowance;

    constructor() {
        balances[msg.sender] = totalSupply;
    }

    function transfer(address to, uint256 amount) public returns (bool) {
        require(balances[msg.sender] >= amount, "Insufficient balance");
        balances[msg.sender] -= amount;
        balances[to] += amount;
        return true;
    }

    function approve(address spender, uint256 amount) public returns (bool) {
        allowance[msg.sender][spender] = amount;
        return true;
    }
}

📚 Smart Contract Fundamentals for Finance

What is a Smart Contract?

A smart contract is code that runs on the blockchain. Once deployed, it's immutable—no one can change its logic. It executes automatically when conditions are met, enabling trustless finance.

Solidity Language

Solidity is the primary language for writing Ethereum smart contracts. It's similar to JavaScript but must be formally verified (often through audits) because contract bugs can lead to lost funds.

EVM (Ethereum Virtual Machine)

The EVM is the "computer" that executes bytecode. Each opcode (operation) consumes gas. Financial contracts must optimize gas efficiency to be economically viable.

Real-World Finance Examples

  • Uniswap: Decentralized exchange (DEX) enabling token swaps
  • Aave: Lending protocol where users deposit assets and earn interest
  • MakerDAO: Stablecoin protocol collateralized by crypto

📚 NFT Economics for Finance Professionals

What Makes an NFT Unique?

An NFT is uniquely identified by a tokenId on the blockchain. The smart contract stores who owns each tokenId. Ownership is immutable and verifiable on-chain.

Token Standards (ERC-721/ERC-1155)

Standards ensure compatibility across platforms. An ERC-721 token can be traded on any marketplace supporting the standard, without the creator's permission.

Royalties & Secondary Markets

Creator royalties are typically enforced by marketplaces (not on-chain). When an NFT is resold, the creator receives a percentage. This creates ongoing revenue for digital assets.

Financial Use Cases

  • Fractional Ownership: Divide expensive assets (art, real estate) into many NFTs
  • Collateral: Use NFTs as loan collateral in DeFi protocols
  • Proof of Ownership: Represent certificates, licenses, intellectual property
