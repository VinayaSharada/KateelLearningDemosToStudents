What this demo is about

Stack smashing is a classic attack where an attacker writes more data than a buffer can hold, overflowing into adjacent memory, overwriting the function's return address, and hijacking control flow.

Learning objectives

  • Understand stack memory layout (locals, saved EBP, return address)
  • See how buffer overflow corrupts the stack
  • Recognize the critical role of return addresses
  • Understand why input validation and buffer bounds matter

Key Insights

  • No bounds checking: The vulnerable function never validates buffer size, allowing overflow.
  • Contiguous stack: Local variables, saved EBP, and return address sit next to each other in memory.
  • Return address matters: When a function returns, the CPU jumps to whatever address is on the stack.
  • Attacker control: By carefully crafting input, an attacker can write specific values to the return address.
  • Defense layers: Stack canaries, ASLR, DEP/NX, and bounds checking all make this attack harder.
